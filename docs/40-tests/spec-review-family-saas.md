実施日: 2026-07-26 / 対象: `../10-specs/family-edition-spec.md`, `../10-specs/saas-diff-spec.md`, `apps/family/`
観点: **矛盾・不要機能**

## 1. 結論

**`../README.md` の「家族版仕様 ＋ 差分仕様 ＝ 事業版の完全な仕様」という前提は、成立していなかった。**

原因は1つで、そこから連鎖している。

```
発音評価を家族版に含めると決め、実装した（§1の訂正）
        ↓ しかし §4・§5・§12・§13 に反映しなかった
家族版仕様が実装より遅れる（テーブル8→7、EF3→2、画面6→5 と記載）
        ↓ 差分仕様書はこの古い数字を「基数」として引用していた
差分の総量が全項目ズレる。発音評価は差分仕様書に1回も登場しない
        ↓
事業版で「発音評価をどのプランで何回まで使わせるか」が未定義のまま
＝ Azure は従量課金なので、原価が青天井になる設計だった
```

**教訓：** 上位の決定（§1）を下位の節に伝播させないと、その文書を基数にしている別文書まで壊れる。

## 3. 実装の不具合（家族版・未デプロイ）

**デプロイすれば確実に顕在化するもの**を修正した。

| # | 内容 | 影響 |
|---|---|---|
| 1 | 中国語 `fine` が **1文字ずつ**に分割されていた（`pinyin({type:"all"})` は文字単位を返す） | 現行アプリの词（単語）分割から**退化**。`segment()` に修正 |
| 2 | 日付が **UTC** で切り出されていた | JST 0〜9時の記録が**前日**として表示される。`jstDate()` を導入して全箇所を修正 |

## 4. 不要と判断した機能

削減の見積は**合計60〜80時間**。

### 家族版

| 項目 | 判断 |
|---|---|
| 家族の最終利用日の共有 | **削除**（実施済み） |
| `checkQuota` の実行時DBアクセス | **中身を1行に**。両分岐が同じ値を返すのに毎リクエストDB往復している。テーブル・列は後付け困難なので**残す** |
| keepalive の自動ping | 娘が週2日使うなら停止しない。**自動pingは条件Aの生シグナルを消す**。手動起動のみにする案 |

**削らないと判断したもの：** `subscriptions` テーブル・RLS全テーブル・エクスポート・設定同期・全件ロード（いずれも後付け困難、または実装済みで削る利得がゼロ）

### 事業版（→ 差分仕様書 §10 に反映済み）

| 項目 | 判断 |
|---|---|
| Pro プラン一式 | **初期に出さない**（分岐点が1人しか変わらない） |
| 深掘り連載・AI添削・優先サポート | **作らない** |
| 人気カテゴリの定期生成＋興味設定 | **後回し**（会員10人時のヒット率20%＝8割が読まれない。固定費1,044円/月） |
| Google / Apple ログイン | **後回し**（Apple は年15,000円。効くのは登録摩擦で、律速は転換率） |
| エラー監視SaaS・レート制限 | **後回し**（乱用対策はクォータが果たす） |
| 既読記録・アーカイブ画面 | **後回し** |
| 独立ページ 11〜13 → **5** | 記事リクエスト／お支払い／退会はセクションに畳む |

## 6. 所見

前回の現行アプリのときと同じ構図だった。**「決めたことを、その決定が波及する全部の場所に書く」が抜けると、文書は静かに壊れる。**

今回は `../10-specs/current-app-spec.md` の棚卸しから発音評価が漏れていたことが起点で、それが家族版仕様 → 差分仕様書 → 事業計画の原価モデルまで、4文書を貫いて欠落していた。

**仕様書は書いた時点ではなく、参照される時点で正しくなければ意味がない。**
`humanoidAsAService/_memory/practices/spec_test_cycle.md`（仕様書・テストサイクル）の「大きな実装を終えたら4点セットで確認する」は、この種の伝播漏れを捕まえるための手順である。
