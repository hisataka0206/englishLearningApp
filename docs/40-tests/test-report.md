## 3. 検出した問題と対応

### 3.1 【実装の不具合】記録タブの「削除」ボタンが動作していなかった

**発見:** テスト A-10（`POST /api/assessments/clear`）が **400** を返した。

**原因:** `do_POST` の冒頭が**前方一致**だった。

```python
if self.path.startswith("/api/assess"):   # ← /api/assessments/clear も飲み込む
    return self._handle_assess()
```

`/api/assessments/clear` が音声評価ハンドラに吸い込まれ、`text` パラメータが無いため `400 text is required` を返していた。
本来の処理（`server.py` の `elif self.path == "/api/assessments/clear"`）は**到達不能な死にコード**だった。

**影響:** 記録タブの発音評価履歴の**削除ボタンが機能していなかった**（`index.html` がこのAPIを呼んでいる）。仕様書 §6 は「`{deleted}` を返す」と書いており、**仕様書どおりに動いていなかった**。

**対応:** パスを完全一致に変更し、`APP_VERSION` を **1.37.1** に更新。回帰テスト A-10 を追加。

```python
# ★前方一致にすると /api/assessments/clear まで飲み込むため、パスは完全一致で見る
if self.path.split("?")[0] == "/api/assess":
```

> **この不具合は前回の「読み合わせ」では見つからなかった。** 静的にコードを読むと `elif` 節が存在するので正しく見える。実際に叩いて初めて到達不能だと分かる。**テストをやる意味がここにあった。**

### 3.2 【仕様書の誤り】削除APIの戻り値

**発見:** テスト A-08 で `{deleted: true}` を期待したが、実際は `{deleted: "<削除したid>"}` だった。

**判定:** **実装が正**。仕様書の `{deleted}` という書き方が中身を示しておらず、真偽値と読めてしまう。

**対応:** 仕様書 §6 を `{deleted: 削除したid}`（真偽値ではない）に修正。移植時に `true` を期待する実装を書くと壊れるため。

### 3.3 【テストコードの不備】3件

いずれもテスト側の誤りで、実装・仕様書に問題なし。記録として残す。

| 内容 | 修正 |
|---|---|
| `save_sentence` の戻り値を id 文字列と誤認 | `{"id": ...}` から取り出すよう修正 |
| C-30 の入力に自動分割対象語が無く、対比が出なかった | `to` を含む文に変更 |
| 抽出JSに DOM 依存行が混ざり Node で落ちた | 最小限の DOM スタブを追加 |

## 4. ★テスト実行そのものが実データを汚染した件（重要な記録）

**発生:** L3 の初回実行で、**利用者の実データ（`apps/local/data/sentences_zh.json`）にテストレコードが1件書き込まれた。**

**原因:** `GET /api/health` は仕様書 §6 に記載のとおり **config を再読込する副作用**を持つ。

```python
def do_GET(self):
    global CFG
    ...
    CFG = load_config()   # ← モジュールグローバルを上書きする
```

テスト側でデータ領域を一時ディレクトリに差し替えていたが、**health を1回叩いた瞬間に設定が実ファイルから再読込され、隔離が外れた。**

**対応:**

1. 混入した1件を**特定して除去**（除去前に `/tmp/backup_sentences_zh.json` へ退避）。全JSONファイルを走査し、**残留なしを確認済み**。
2. テストハーネスを修正 — `load_config` / `make_drive` / `make_notion` / `make_azure` をスタブに差し替え。
3. **ガードを二重に追加** —
   - **A-00**: health 呼び出し**後**にデータ領域が一時ディレクトリのままであることを検査
   - **A-99**: テスト終了時、実データにテストレコードが混入していないことを検査
4. `test-spec.md` §4 に、この副作用と対策を明記。

**現在の実データ件数（正常）**

| ファイル | 件数 |
|---|---|
| `articles_zh.json` | 29 |
| `assessments.json` | 10 |
| `sentences.json` | 9 |
| `sentences_zh.json` | 1 |
| `words.json` | 6 |
| `words_zh.json` | 3 |

> **教訓:** 稼働中のアプリに対してテストを書くときは、隔離が「効いている」ことを**テスト自身に検査させる**必要がある。設定を一度書き換えるだけでは足りない。
