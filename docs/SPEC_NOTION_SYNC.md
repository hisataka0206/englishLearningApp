# 記事モード ＆ Notion同期 仕様書（設計案・実装前）

本書は、既存アプリに「[[記事モード]]」を新設し、[[Notion]]の中国語学習記事と[[双方向同期]]する機能の設計案。実装前の合意用ドラフト。

## 1. 目的

Notionで運用中の[[中国語勉強用記事]]（週1本・約600字・全文[[拼音]]付き・句ごとに中文/拼音/日本語の3行セット＋重要語彙表）を、アプリの[[発音練習]]UIで句・音節単位に練習できるようにする。さらにアプリで付けた[[失敗履歴]]（[[Fail]]）をNotionの記事へ書き戻し、既存の集計運用につなげる。

学習上の狙いは、拼音は読めるが[[漢字と発音の結びつき]]が弱い課題の解消（アプリの節プレイヤー＋将来のルビ表示で視覚的に補助）。

## 2. 全体構成（既存温存・UI流用）

現行の3画面（メイン練習／履歴／言語トグル）は**そのまま維持**する。新たに「[[記事]]」ページを1つ追加し、ヘッダーから切り替える（履歴ページと同じナビ方式）。記事ページのUIは既存部品を流用する：

- 記事一覧（履歴ページの表形式を流用）
- 記事を開くと句が並び、各句は既存の[[フレーズプレイヤー]]（節分割・再生/一時停止・速度・タップ再生）で練習
- 拼音表示・[[音声合成]]（zh-CN）・Fail記録は既存機能をそのまま利用
- 重要語彙は既存の単語帳表示を流用

## 3. データモデル

### アプリ側（新規ファイル）

Driveに `articles_zh.json` を追加（既存の `sentences_zh.json` 等とは別区画）。

```
Article {
  id: 固有ID,
  notion_page_id: 記事のNotionページID,
  title: "2026-07-01 北京银河通用…",
  date: "2026-07-01",
  sentences: [ { idx: 1, zh: "中文…", pinyin: "pīnyīn…", ja: "日本語訳…",
                 fails: [ {label, syllable, time} ] } , … ],
  vocab: [ { zh, pinyin, ja } … ],
  imported_at, updated_at
}
```

拼音はNotion側の[[全小文字]]表記をそのまま採用（アプリの自動生成では上書きしない）。

### Notion側（既存構造・変更しない）

記事子ページ ＝ 出典情報＋「中文要约＋拼音」（句ごとに中文/拼音/日本語トグル）＋重要語彙表。既存のインラインFailコメントは読み取り対象にできるが**新規作成はしない**（後述）。

## 4. Notion接続

アプリサーバー（`server.py`）が[[Notion REST API]]を直接呼ぶ。[[インテグレーショントークン]]を `config.json` の新セクション `notion` に外部化（Driveのトークン同様、git管理外）。

```
"notion": {
  "token": "PUT_YOUR_NOTION_INTEGRATION_TOKEN",
  "articles_parent_page_id": "36dcd557226180e4afe0cf5739016724",  // 中国語勉強用記事
  "api_version": "2022-06-28"
}
```

Notion側で対象の親ページ（および子記事）にインテグレーションを接続しておく必要がある。

## 5. Notion → アプリ（取り込み）

トリガー（確定）：**初回のみ**親ページ（中国語勉強用記事）を指定する。以降は「記事を更新」操作で、親ページ配下の子ページのうち**まだ取り込んでいない新規記事を自動検出して取り込む**（`notion_page_id` の差分で判定）。個別選択は不要。手動で特定記事を再取り込みする補助操作は残す。

解析仕様：本文の「**第N句**」ブロックから `中文：` / `拼音：` 行を句ごとに抽出し、直後の日本語トグル（details）から訳を取得。重要語彙表を vocab として取得。既にインラインFailがあれば `fails` に読み込む（双方向の読み取り側）。

取り込み後はオフラインでも練習でき、句単位で発音・Fail記録が可能。

## 6. アプリ → Notion（失敗履歴の書き戻し）

**方式：記事ページ末尾に「失敗履歴」テーブルを作成/更新**（インラインコメントは技術的に不可のため採用しない）。

- 記事の末尾（重要語彙表の下）に見出し「## 失敗履歴（アプリ記録）」とテーブルを1つ設ける。
- 列：`日付` / `句` / `該当（拼音）` / `該当（漢字）` / `ラベル`。
- アプリで練習中にFailを付けると、サーバーがこのテーブルへ行を追記（または全体を再生成して[[upsert]]）。
- 既存のインラインFail運用とは別系統として明示（見出しで区別）。将来 pinyin-fail-report スキルをこのテーブルも集計できるよう調整する（本アプリ機能の完成後に対応）。

書き戻しの同期タイミング（確定）：**手動ボタンのみ**。Failはアプリ内（Drive）に随時記録し、「Notionへ反映」ボタンを押したときにまとめて末尾テーブルへ書き戻す（Fail都度の自動送信はしない）。

## 7. 失敗の粒度

句単位に加えて、**音節・単語単位**でFailを付けられる（論点B=Yes）。フレーズプレイヤーの各節・各音節（ルビ実装後は各字）に対してFailボタンを出す。粒度は `fails[].syllable` に該当拼音（と対応漢字）を保持し、失敗履歴テーブルに反映する。

## 8. トリガー・UI（推奨デフォルト）

- 初回設定で親ページを指定（`config.json` 既定値あり）。
- 記事ページ上部に「Notionから記事を更新」ボタン（新規記事を自動検出して取り込み、一覧更新）。
- 記事一覧は日付降順の表。行タップで句一覧＋プレイヤーを開く。
- 各句：発音（🔊）・Fail（該当箇所を選んで記録）。既存UIを流用。
- 「Notionへ反映」＝手動ボタンのみ。未反映のFail件数をバッジ表示。

## 9. 制約・非対応

- Notion既存Failと同じ「音節へのインラインコメント」の**新規作成はAPI不可**。よってアプリ発のFailは末尾テーブルに集約する（§6）。
- 翻訳系のローカルLLMとは独立。記事取り込み・書き戻しはNotion接続時のみ動作（Mac起動＋トークン設定が前提）。
- pinyin-fail-report スキルの改修は本機能完成後に別途行う。

## 10. 実装ステップ（案）

1. `config.json` に `notion` セクション追加、`notion_client.py`（REST薄ラッパ：token更新不要、ページ取得・ページ更新・コメント）を新設。
2. サーバーに記事API：`/api/articles`（一覧取得＝Notion親配下列挙）、`/api/articles/import`（解析保存）、`/api/articles/list`（ローカル一覧）、`/api/articles/fail`（Fail記録＋末尾テーブル書き戻し）。
3. UIに「記事」ページを追加（既存プレイヤー・履歴表・単語帳表を流用）。
4. 失敗履歴テーブルの生成/upsert 実装。
5. 検証（取り込み解析・Fail書き戻しの往復）。
6. （別タスク）pinyin-fail-report スキルを末尾テーブル対応に調整。

## 11. 確定事項（2026-07 合意）

- 取り込み：初回のみ親ページ指定、以降は新規記事を自動検出して取り込み。
- 失敗履歴テーブルの列：`日付` / `句` / `該当（拼音）` / `該当（漢字）` / `ラベル`。確定。
- 書き戻し：手動「Notionへ反映」ボタンのみ（Fail都度の自動送信なし）。
